1. Core Concepts & Architecture

KPRM2 is an enterprise Case and Verification Management System designed for high-volume background checks and investigations.

  • Cases: The root entity representing a specific verification applicant or file ingestion.
  • Tasks & Case Tasks: Tasks are global verification templates (e.g. Financial Statements, Banking, ITR / ITO, Address Check). Case Tasks are the specific assignments bound to a Case.
  • Dynamic Task Meta (Schema-free Fields): Task forms are generated dynamically using configurable metadata attributes without requiring physical table schema alterations.
  • Client Dashboard Isolation: Selecting a client in the top navigation bar isolates metrics, progress breakdowns, and operational charts specifically to that client.
  • Role-Based Access Control (RBAC): Granular field-level and operational permissions configured per user role (DEV, Admin, Manager, BEO, Verifier, Reviewer).

2. User Roles & Lifecycle Workflow

Role Operational Scope Configuration Permissions
DEV Developer root access, telemetry logs, webhook debugging, system settings, database management. Root Developer All System Tools, APIs & DB.
Admin Full access across all cases, task assignment, verification processing, reviews, and reporting. Full Control Settings, API, Comms, Schemas.
Manager Supervises all operational workflows, reviews tasks, and generates client reports. Operational Read-only settings.
BEO Creates cases, assigns case tasks to Verifiers or WhatsApp groups, and reviews completed work. No settings access.
Verifier Processes assigned tasks, inputs financial/field findings, uploads documents, and submits outcomes. Restricted to assigned tasks.
Reviewer Cross-checks Verifier submissions, customizes dynamic remarks using #tags#, and finalizes status. Review queue access.

4. Digital Verification Engine & Remote APIs (/settings?tab=external_api)

The Digital Verification Engine manages automated background communication with external verification partner servers for Banking and ITR / ITO verification.

Outbound Remote Endpoints

  • Banking Endpoint (update_banking): Transmits ref_id, ref_site, bank_name, account_no, txn_details, and requirement.
  • ITR Endpoint (update_itr): Transmits ref_id, ref_site, name_of_document, pan, ay, and requirement.
  • Engine Master Switch & Auto-Dispatch: Configure whether tasks automatically dispatch on creation or require manual triggering via the Case Tasks action button.

Inbound Webhook Receiver (/api_task_update)

When the external partner completes verification, their server calls our webhook with the resolution:

  • Payload: ref_id (Task ID), status (Positive/Negative/CNV), remarks, and optional attachment_link.
  • Auto-Processing: Automatically marks task status as Verified, saves the verifier remarks, downloads any remote PDF/image attachment directly into local storage, and advances the task into the Review Queue.

5. API Live Diagnostic Tools (/settings?tab=api_diagnostics)

A dedicated diagnostic sandbox to test endpoint connectivity and simulate callbacks without touching live cases:

  • 1. Outbound Payload Tester: Test cURL dispatch to remote banking or ITR servers with custom PAN, AY, Bank, or Account inputs. Live JSON payload and server responses display in the telemetry console.
  • 2. Inbound Webhook Simulator: Simulate partner callbacks for any Task ID with custom statuses and remarks to test workflow progression.
  • Inbound Webhook Activity Log: Complete audit log of recent incoming callbacks with timestamps, client IP addresses, and HTTP status codes.

6. Custom Functions Reference (30+ Helper Formulas)

Used in Manage Structures (case ingestion forms) and Manage Reports (report configurations) to compute dynamic values on-the-fly.

pick_up_date({case_id})

Date of Pick Up (case creation timestamp). Supports optional custom format like pick_up_date({case_id}, 'd-m-Y') (defaults to 'Y-m-d').

reverted_date({case_id})

Date of Reverted (latest verification timestamp). Supports optional format like reverted_date({case_id}, 'd-m-Y') (defaults to 'Y-m-d').

tat({case_id})

Turnaround Time (TAT) in days automatically computed between pick_up_date and reverted_date.

current_date()

Returns current server date. Supports optional custom format like current_date('d-m-Y') (defaults to 'Y-m-d').

current_month()

Returns current month and year (e.g. 'Oct 2026').

format_date({Date}, {Format})

Formats any raw date into standard display format (e.g. 'd-M-Y').

financial_view_btn({case_task_id})

Interactive button opening the financial statements comparative modal with discrepancy indicators.

view_ft({case_task_id})

Renders the full P&L and Balance Sheet comparative matrix table for reports/PDFs.

financial_remarks({case_task_id})

Generates official financial observations narrative with applicant, FY, PAN, and numbered match/non-match items.

task_count({case_id})

Total number of tasks assigned to the specific case.

type_of_document({case_id})

Comma-separated list of assigned tasks and counts (e.g. ITR-2, Address-1).

fe_name({case_id})

Comma-separated list of Field Executives (Verifiers) assigned to the case.

task_view({case_task_id})

Generates an interactive 'View Task' button opening modal details.

task_remarks({case_task_id})

Formatted string of task final status and remark, translated with client keywords.

case_status({case_id})

Summary of task counts per status (e.g. '2 Completed, 1 Pending (67% Completed)').

case_stage({case_id})

Workflow progress stage ('Pending', 'In Progress', 'Completed').

case_view({case_id})

Generates an interactive 'View Case' popup modal button.

overall_status({case_id})

Aggregates task remarks and computes final case status keyword.

stamp([case_id], [width])

Returns HTML image tag of the client agency stamp for official reports with automatic width.

all_task_remarks({case_id})

HTML table summary (Task Name | Status | Remarks) of all tasks for reports.

combine_text({Text1}, {Text2})

Concatenates two or more strings together with a space.

client_name({case_id})

Returns the client organization name associated with the case.

7. Communication Hub & Green API Live WhatsApp Suite (/whatsapp)

Supports multi-account Email (SMTP) and WhatsApp (Green API) with task-type routing, automated events, and an embedded two-way chat messenger.

In-App Live WhatsApp Chat & Instance Manager

  • Live 2-Way Messenger: Send and receive WhatsApp messages, attachments, documents, and notifications directly from the web app.
  • Live QR Code Login & Instance Switcher: Switch between WhatsApp accounts, check live connection status (authorized, notAuthorized), view real-time QR code for linking, and restart/logout instances.
  • Privacy-Masked Numbers: Contacts and headers mask phone numbers (middle digits hidden as XXXX) and clean technical suffixes like @c.us and @g.us.
  • Clickable URLs & Document Previews: URLs in messages are automatically hyperlinked, and documents (PDF, DOCX, XLSX) can be viewed and downloaded directly from chat.

💬 Event 1: On Task Assigned

Channel: WhatsApp (Green API)

Recipient: Assigned Verifier or Group (users.mobile)

Sender: Task-Type assigned instance (e.g. ITR instance for ITR tasks).

Payload: Dispatches Task Name, Case ID, Client, and all assigned dynamic fields using #Task_Fields#.

✉️ Event 2: On Case Reviewed

Channel: Email (SMTP)

Recipient: Client Official Email (clients.email)

Condition: Triggered when client has Email Reporting enabled.

Payload: Dispatches full verification report summary, case details (#Case_Fields#), and task remarks.
